## 🧩 Техническое задание: Сохранение результатов парсера World-Art в Supabase

### 📌 Цель

Сохранять результаты парсинга OST-данных с World-Art в Supabase с учетом версии парсера, чтобы:

* Избежать повторного парсинга, если данные уже есть и версия парсера актуальна.
* Иметь возможность логировать историю изменений.
* Хранить видеоролики OST локально (через Supabase Storage).
* Поддерживать версионирование и изоляцию от бизнес-моделей приложения.

---

### 📐 Структура Supabase

#### Таблица: `wa_parse_logs`

> Хранит *результаты конкретного парсинга*, не мешая бизнес-данным.

| Поле                | Тип       | Описание                         |
| ------------------- | --------- | -------------------------------- |
| `id`                | UUID (PK) | Уникальный ID записи             |
| `worldart_anime_id` | int       | ID тайтла в World-Art            |
| `shikimori_id`      | int       | (опц.) ID в Shikimori            |
| `parser_version`    | string    | Версия парсера, руками задается  |
| `parsed_at`         | timestamp | Дата парсинга                    |
| `osts`              | jsonb     | Массив объектов `OST` (см. ниже) |
| `raw`               | jsonb     | (опц.) Сырой результат парсера   |

> Можно добавить `unique(worldart_anime_id, parser_version)` для исключения дубликатов.

---

### 🧾 Модель данных OST (в поле `osts`)

Используется структура:

```ts
interface OST {
  id: number;
  unparsed_type: string;
  type: "OP" | "ED" | "TRAILER" | "UNRECOGNIZED";
  href: string;
  video: string; // оригинальная ссылка с World-Art
  title: string;
  authors: Author[];
  ost_order: number;
  storagePath?: string; // путь в Supabase Storage, если файл загружен
  downloadError?: string; // ошибка при скачивании, если была
}

interface Author {
  id: number;
  name: string;
  href: string;
  role: string;
}
```

---

### 🗃 Хранилище видео

**Supabase Bucket:** `ost_videos`
**Путь:** `worldart/{worldart_anime_id}/{ost_id}.mp4`

Для каждого OST-файла:

* Скачать `video` по ссылке из World-Art.
* Залить в `ost_videos` и сохранить путь в `storagePath`.
* В случае ошибки — сохранить описание ошибки в `downloadError`.

---

### ⚙️ Логика работы API `/api/getOst`

1. **Проверка наличия записи:**

   * Ищем запись по `worldart_anime_id` и `parser_version` в таблице `wa_parse_logs`.
   * Если есть — возвращаем результат из Supabase без повторного парсинга.

2. **Если нет записи:**

   * Запускаем парсер World-Art по переданному `worldart_anime_id`.
   * Полученные OST-данные сохраняем в `wa_parse_logs`, включая:

     * `parser_version` — передается в запросе
     * `parsed_at = now()`
     * `osts` — массив OST с вложенными авторами и ссылками на видео
     * `raw` — (опционально) исходный ответ парсера для отладки

3. **Обработка видео:**

   * Для каждого OST с полем `video`:

     * Пытаемся скачать файл по URL
     * Заливаем файл в Supabase Storage (`ost_videos/worldart/{anime_id}/{ost_id}.mp4`)
     * Успешный результат — путь сохраняется в `storagePath` поля `OST`
     * При ошибке — сохраняем описание ошибки в `downloadError`

4. **Ответ:**

   * Возвращаем клиенту финальный объект с данными из Supabase, включая OST, пути к видео или ошибки загрузки.

   * Если видеофайлы приватные, для доступа создаются **signed URL** через `supabase.storage.from(bucket).createSignedUrl(path, expiresInSeconds)`.

   * Эти временные ссылки можно безопасно отдавать клиенту (например, на 1 час), вставлять в `<video src=...>`, не раскрывая путь напрямую.

   * Возвращаем клиенту финальный объект с данными из Supabase, включая OST, пути к видео или ошибки загрузки.

### 🚨 Ошибки и обработка

* Если Supabase не доступен — возвращаем 503.
* Если ошибка при парсинге — 500 + лог.
* Если файл не скачался — продолжаем парсинг, помечаем в `downloadError`.

### 🧠 Как работает текущий парсер World-Art

В основе лежит два этапа:

#### 1. `getLinkList(id: string)`

Получает список ссылок на OST по ID аниме с World-Art (страница `animation_trailers.php`).

* Парсит HTML с помощью `cheerio`
* Извлекает `href`, `название` (тип OST: OP/ED/трейлер)
* Определяет `OstType`, `ost_order`, `id`

#### 2. `getFullOST(ost: Partial<OST>)`

Получает подробную информацию по каждому OST:

* Загружает HTML страницы OST по `href`
* Парсит `title`, `video.src`, `authors` (с ролью и ссылкой)
* Авторы собираются через `getSiblings()` — обходит `p.review`
* Финально собирается полный `OST`-объект

#### Дополнительно

* В режиме разработки (`NODE_ENV=development`) используется `memoize`, чтобы кешировать результаты парсинга и не делать лишние запросы

#### API `/api/getOst`

* При `GET` запросе с `waId`:

  * Парсит список OST-ов через `getLinkList`
  * По каждому вызывает `getFullOST`
  * Возвращает массив объектов `OST`

* Ошибки и пустые значения не выбрасываются — просто возвращаются как есть

* Все строки на сайте в `windows-1251` — используется `TextDecoder` для декодинга
